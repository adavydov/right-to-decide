# Право на решение

**Как остаться авторами будущего рядом с более сильным интеллектом**

Рабочий репозиторий футурологического манифеста-проекта: авторские тексты, редакция и сайт для чтения.

[Сайт](https://adavydov.github.io/right-to-decide/) · [Манифест](https://adavydov.github.io/right-to-decide/manifesto/) · [Инструкции агентам](AGENTS.md)

## Конституция и действующий план

[CONSTITUTION.md 1.2.1](CONSTITUTION.md) — единый содержательный источник, введённый в рабочие правила по поручению инициатора 6 сентября 2026 года. [Word 1.2.1](public/manifesto/Pravo_na_reshenie_Manifest_Constitution_v1.2.1.docx) — полная читательская копия; принятие всеми соавторами и параметры реального пилота не объявлены согласованными.

Главный вопрос: **как спроектировать развитие человека, когда оно перестаёт быть необходимым условием получения технического результата?** Ответ — «образование, которого нет»: развитие встроено в деятельность, которую люди способны осваивать, продолжать и менять рядом с более сильным интеллектом. Работающая система, развитие участников и самостоятельное продолжение проверяются раздельно.

[Содержание 5.1](manuscript/2026-09-05-rebuild/contents-v5.1.md) следует §7: пролог, шесть частей, восемнадцать глав и эпилог. [Рабочий пакет](manuscript/2026-09-05-rebuild/README.md) разрешает версии. [Аудит согласования](docs/editorial/CONSTITUTION-ALIGNMENT-v1.1-2026-09-06.md) описывает совпадения, изменения и ограничения проверки существующих глав.

[Карта применения патча 1.2.1](docs/editorial/CONSTITUTION-PATCH-v1.2.1-2026-09-06.md): Патч 1.2.1 действует перспективно: главы 1–7 текущей сборки уже написаны и не перерабатываются ради С09; текущие задания не останавливаются и не запускаются заново. Начиная с ещё не написанной на момент перехода главы 8, С09 включается только там, где меняет объяснение, механизм или вывод. Краткое основание включения либо пропуска фиксируется в задании главы; квоты упоминаний нет. Старые выпуски и их приёмки сохраняются. Единственное разрешённое дополнение написанного текста — отдельная версия пролога 2.1 с неизменным текстом 2.0 внутри.

## Редакционный процесс

Начать с конституции целиком и [AGENTS.md](AGENTS.md), затем открыть [действующие правила](docs/editorial/README.md). Принципы 3.1, стиль 5.1, процесс 3.1 и отдельные контракты ролей и приёмки заменяют прежний литературный режим.

Девять слоёв — философский, космический, исторический, образовательный, предпринимательский, общественный, антропологический, Омега и социально-экономический — имеют [собственные репозитории материалов](docs/editorial/LAYER-REPOSITORIES-01-v2.1.md). Космическое предприятие — сквозной мысленный эксперимент. Условия сравнения, изменяемые параметры и чувствительность выводов ведутся в паспорте по приложению Д и журнале между главами. История проверяет механизм, сценарий исследует условия, пилот даёт данные. Вымышленные герои, сцены, диалоги и «Тетрадь Омега» исключены.

Перед новой главой: конституция, пролог, материалы ведущих слоёв и книжная память → задание по приложению А и Pyramid → композиция → текст → проверка источников и сильного возражения → ритм и холодное чтение → приёмка. У каждого значимого проверяемого утверждения есть источник, точный фрагмент и границы вывода. Все 12 применимых критериев §11.2 получают минимум 3 из 4; усреднение не скрывает слабое основание. Книга отдельно проверяется как самостоятельный аргумент без космического примера и как согласованный мысленный эксперимент при чтении только космических фрагментов.

Старые каноны и выпуски сохраняются как история. Обновление правил не означает, что существующие главы уже переписаны или заново приняты. Оригиналы и частные карточки общей book-memory и девяти репозиториев не публикуются. Операционные обязательства остаются только в Jira.

## Текст, исходники и структура проекта

[Литературная редакция 6.0](manuscript/2026-09-05-rebuild/chapters-v6/README.md) содержит восемнадцать пересобранных глав и эпилог. Пролог 2.1 выбран отдельно, мастер 2.0 сохранён. Рядом с каждым литературным разделом в оглавлении и ридере доступно скачивание DOCX; сайт и Word используют один принятый исходник.

Содержательный источник — CONSTITUTION.md; план — manuscript/2026-09-05-rebuild/contents-v5.1.md. Пролог и существующие главы сохраняют свои версии. src/data/book.json содержит текущую веб-проекцию. scripts/publish-author-contents.py воспроизводит исторический выпуск 4.0 и не должен запускаться поверх текущих глав; scripts/publish-manuscript.py собирает явно выбранные литературные главы и проверяет действующий выпуск. src/data/previous-edition.json сохраняет прежний корпус для /archive/; повторный DOCX-импорт не является способом обновления текущего выпуска.

Текущая обложка — public/images/book-cover-contents-v4.png, скачиваемое содержание — public/book/contents-v5.1.md. Авторские Markdown и манифесты сохраняются в Git; оригиналы книг, личные карточки и материалы book-memory/ остаются локальными.

## Локальная разработка и обновление сайта

Рабочий Git-корень — отдельный репозиторий **`right-to-decide`**. В исходной папке «Ньютон книги» он находится в `right-to-decide-site/`; родительский `edu40-monograph` обслуживает книгу «Инженерное образование 4.0». Все команды ниже выполняются из корня `right-to-decide`.

Требуется Node.js 24+. Импорт рукописи использует Python 3 и стандартную библиотеку.

```powershell
npm ci
npm run dev
```

Полная проверка в режиме GitHub Pages:

```powershell
$env:NEXT_PUBLIC_BASE_PATH = '/right-to-decide'
npm run check
```

Команда выполняет lint, TypeScript, проверку контента, сборку и проверку статического экспорта. Для изменений только редакционной документации достаточно проверить ссылки, точность переноса и Git diff; литературная приёмка главы проводится отдельно.

Проверка исходников: `python scripts/publish-manuscript.py --check`. Исторический DOCX-импорт описан в [book-import.md](docs/research/book-import.md); его нельзя запускать поверх текущей Markdown-редакции без отдельной миграции.

Сайт включает отдельный /manifesto/, /contents/, /read/prologue/, /read/contents/, /archive/ и страницы авторов, библиотеки и вики. Старый /read/preface/ ведёт к прологу. Плановые главы не имеют ссылки чтения; доступность определяется фактическим составом выпуска.

Push в `main` запускает существующий [GitHub Actions workflow](.github/workflows/deploy-pages.yml): проверку и публикацию статического сайта. Документы в `docs/` сами по себе не добавляют главы в читалку.

Визуальная основа сайта: тёплый светлый фон, тёмная плавающая навигация, крупная гротескная типографика и просторные медиа-модули; референс — brand.ai. Спецификации находятся в `docs/research/`, снимки — в `docs/design-references/`. Используются собственный бренд и авторские изображения; системный гротеск заменяет лицензируемый ABC Monument Grotesk. Атрибуция фотографий: [authors-2026-09-05.md](docs/research/authors-2026-09-05.md).
