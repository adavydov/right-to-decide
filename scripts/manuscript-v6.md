# Сборка рукописи 6.0 и файлов Word

Исходники: `manuscript/2026-09-05-rebuild/chapters-v6/chapter-01.md` … `chapter-18.md`, `epilogue.md`. Пролог выбирается явно в `acceptance.json`; по умолчанию это неизменённый мастер `prologue-v2.0.md`. Дополненная 2.1 имеет собственную независимую проверку. План 5.1 получается из §7 Конституции: его текст сохранён при переходе с 1.1 на 1.2.1. Ни каталог с исходниками, ни наличие файла не означают разрешения его публиковать.

Поддерживаемый Markdown: первый `#` с точным названием из содержания (у номерной главы допустимо опустить «Глава N.»); обычные абзацы; `##`/`###`; `**жирный**`, `*курсив*`; ссылки `[название](https://...)` и `[название][1]` с определением `[1]: https://... "необязательное название"`; нумерованные/маркированные списки без вложенности; `---` или `⸻`. Источники и примечания можно оформить заключительным разделом с обычными ссылками. Неподдерживаемый синтаксис останавливает сборку.

Редактор после независимого чтения создаёт `chapters-v6/acceptance.json`:

```json
{
  "schemaVersion": 1,
  "reviewer": "идентификатор независимого редактора",
  "chapters": [
    {
      "id": "chapter-01",
      "sha256": "SHA-256 точных байтов принятого Markdown",
      "status": "accepted",
      "review": "manuscript/2026-09-05-rebuild/chapters-v6/editorial/reviews/chapter-01-review.md",
      "reviewSha256": "SHA-256 точных байтов независимого отзыва"
    }
  ]
}
```

В записи допустим собственный `reviewer`; для эпилога id — `epilogue`. Генератор сверяет закреплённые хэши текста и отзыва, но не оценивает качество текста и не присваивает приёмку. Изменение принятой рукописи или рецензии требует актуального редакторского решения и обновления хэша. Отзывы внутри `chapters-v6/` сохраняют точные байты через `.gitattributes`.

При переходе на 1.2.1 поле верхнего уровня `constitutionVersion` задаёт действующий канон. В каждой записи `constitutionVersion` сохраняет основание именно её приёмки: у глав 1–7 это 1.1, у следующих — 1.2.1. `constitutionBasis` содержит путь и SHA-256 соответствующей конституции (для 1.1 — архив), `supportingReviews` — записи `{path, sha256}` отдельных экономических проверок. Изменившийся файл отклоняется; файлы и контрольные суммы входят в манифест выпуска.

Для публикации дополненного пролога поле верхнего уровня `prologue` содержит `path`, `version`, `status: "accepted"`, `sha256`, `review`, `reviewSha256` и при необходимости `reviewer`. Изменённый пролог не получает статус принятого автором мастера автоматически: сборщик требует отзыв по его точным байтам. `masterPrologue` в выходном манифесте отдельно сохраняет путь и хэш неизменённой 2.0. Это позволяет публиковать заказанное автором и независимо проверенное дополнение 2.1, не объявляя его новым мастер-образцом.

```powershell
# Полный выпуск после редакционной приёмки всех его разделов
python scripts/publish-manuscript.py --edition v6 --chapters 1-18 --epilogue

# Либо последовательный выпуск явно принятых глав, с полным текущим выбором
python scripts/publish-manuscript.py --edition v6 --chapters 1-3

# Проверка сохранённой версии; не меняет файлы
python scripts/publish-manuscript.py --check

$env:NEXT_PUBLIC_BASE_PATH = '/right-to-decide'
npm run check
```

Выходы: `src/data/book.json`, `chapters-v6/release-manifest.json`, `public/book/chapters/{id}-v{version}.docx`. DOCX настоящие пакеты OOXML с абзацами, стилями, действующими гиперссылками и номерами страниц. Для генерации достаточно стандартной библиотеки Python; LibreOffice не требуется. Текст и ссылки Word сверяются с теми же блоками, которые получает сайт. ZIP имеет фиксированные метаданные для воспроизводимости побайтовой проверки.

Манифест выпуска имеет `schemaVersion: 2`, `editionVersion: "6.0"`, `architectureVersion: "5.1"`, `chapterNumbers`, `includesEpilogue`, хэши конституции, выбранного пролога и мастера, глав, приёмки, отзывов, DOCX, сборщиков и веб-проекции. Архив предыдущей редакции проверяется без изменения. `book.version` остаётся версией архитектуры 5.1; версия каждого нового литературного текста — 6.0, мастер-пролога — 2.0, дополнения пролога — 2.1.

Сборка не выполняет git commit/push. Push в main отдельно запускает существующий GitHub Pages workflow.

## Полный выпуск книги

Выбор всех глав `1-18` вместе с `--epilogue` требует двух независимых общекнижных отзывов в `acceptance.json`: `bookReviews` с идентификаторами `argument-without-space` и `space-continuity`. Каждый содержит `status: accepted`, локальный `path`, SHA-256 самого отзыва и `sourceHashes` для опубликованного пролога, всех глав и эпилога. Изменение текста или отзыва требует актуальной приёмки и новой сборки. Эти отзывы входят в идентичность выпуска и его манифест.
