# Выпуск 10.1

Отдельный генератор `release_v10_1.py` обслуживает 28 разделов: P00, C01–C11, C11A, C11B, C12–C24, E00. Адреса вставок — `chapter-11a` и `chapter-11b`. Старые генератор 10.0, парсер и OOXML-компоненты сохраняют свои байты. Новый код не открывает сервер, не отправляет заметки и не публикует сайт.

## Входы

`--source` указывает рабочий комплект. Требуется `editorial/acceptance-v10-1.json`, который фиксирует точные 28 источников, отдельных авторов и принимающих читателей, их безопасные свидетельства и пять проверок всего корпуса. Политики в определённом порядке: CONSTITUTION.md, planning/chapters.json, editorial/QUALITY_GATES.md, BOOK_METADATA.json. Заглавие, подзаголовок и последние фразы берутся из закреплённых метаданных.

Поле authorApproval обозначает разрешение публиковать, а не чтение человеком: scope `publication-authorization`, reviewer `user-direct-instruction`, decision `authorized`, текущий sourceSetSha256. `authorityEvidence` фиксирует SHA `editorial/AUTHOR_DECISION_2026-09-13_FINAL_PATCH.md`; `evidence` — компактную запись того же разрешения с текущим набором источников. Она не получает статус независимого литературного чтения.

Публичные пакеты отдельно требуют editionVersion 10.1, decision accepted и разных author/reviewer:

- public/research-v10/manifest.json: INDEX и M01–M05, явные файлы воспроизведения каждой модели.
- public/library-v10/manifest.json: cards с SHA public/library-source-cards.json и точные counts. Каталог для совместимости получается из этих же читательских карточек. Числа источников и карточек вычисляются из массива.
- public/editorial-v10/manifest.json: team, text, manifesto; 13 ролей, version 10.1 и темы существующего каталога.
- public/essence-v10-1-manifest.json: content с SHA public/essence-v10-1.json; все 28 разделов и тот же подзаголовок.

Внешние оригиналы и частная библиотека не читаются коллектором. Старые пути внутренних рецензий и предыдущих частных manifest не входят в публичные свидетельства. Полный текст научного досье нельзя экспортировать вместо краткой записи приёмки.

## Подготовка, проверка и установка

`python scripts/release_v10_1.py source-set --source <комплект>` читает 28 файлов и сообщает их SHA, ничего не принимает.

`python scripts/release_v10_1.py prepare --source <комплект> --stage <новая-папка-в-worktree>` выполняет всю проверку входов до создания папки. Сборка сохраняет точные исходники, веб-проекцию, Markdown, DOCX, PDF, отдельные DOCX глав и публичные пакеты. После преобразования повторно сверяются исходники, приёмки, генераторы и публичные данные.

DOCX проверяется по полному видимому тексту и началу каждого раздела. PDF проверяется по полному тексту, включая лишние символы; исключается только структурно распознанный нижний номер страницы. Обложка сохраняет исходный PNG и его пропорции; обложечный код читает размеры файла и не растягивает его под старый формат. Текстовые поля PDF не заменяются приблизительным поиском нескольких фраз.

`python scripts/release_v10_1.py check --stage <папка>` восстанавливает проекции из принятых байтов, проверяет состав всех файлов и связи свидетельств. Корень manifest — manuscript/v10-1/release-manifest.json. Данные сайта сохраняют текущие имена research-v10.json, library-v10.json, editorial-team-v10.json, manifesto-v10.json; карточки находятся в library-source-cards.json, «Суть» — в essence-v10-1.json. Скачивания имеют версию v10.1.

`python scripts/release_v10_1.py install --stage <папка> --snapshot <частный-ZIP-вне-Git>` допускает переход с точной текущей 10.0 либо повторную установку того же releaseId. До замены сохраняются существующие перезаписываемые файлы и прежний manifest; ZIP проверяется по CRC и байтам. Это снимок затрагиваемых файлов, не архив всего репозитория. При исключении во время локальной установки прежние целевые файлы восстанавливаются. Удаление старых публичных маршрутов и публикация выполняются отдельным контуром.

Новый выпуск не зависит от наличия публичных страниц или файлов версии 9. Снятие старых редакций не требует переписывать их исторические свидетельства.

## Проверки кода

`python scripts/test-release-v10-1.py -v` — технические временные fixtures: 28 разделов, SHA, независимость, разрешение автора, публичные поля, пропорции обложки, полный PDF-текст, проекции, точный снимок и локальный переход. Преобразование PDF в комплексной fixture заменено тестовой функцией; это не проверка реального выпуска.

`node --test scripts/test-content-v10-1.mjs` — архитектура, адреса вставок, подмена источника, обязательная M05 и безопасные пути.

После установки check-selected-release.py и check-selected-content.mjs выбирают проверки 10.1. Прежняя 10.0 продолжает направляться в свой замороженный генератор. Перед Git необходимо сохранить точные байты новых закреплённых файлов через адресные правила `-text`; разрешение выпуска и тесты не заменяют эту проверку переноса.
