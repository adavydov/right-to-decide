# Импорт авторской рукописи

Источник: авторский файл `Pravo_na_reshenie_04.09.26.docx`, предоставленный пользователем локально в Downloads. Редакция: **4 сентября 2026 года**. Дата импорта: 5 сентября 2026 года. SHA-256 исходного файла записан в `src/data/book.json → source.sha256`.

Это перенос имеющегося авторского текста, а не редакторская или научная проверка. Формулировки, библиография, внутренние ссылки, сведения об издании и оставленные в рукописи издательские поля перенесены из источника.

## Результат и полнота

- 38 разделов: вступительные материалы, введение, **18 глав в 6 частях**, заключение, **10 приложений А–К**, список литературы.
- 3 251 исходный абзац, включая абзацы таблиц и поле оглавления; 68 пустых абзацев не создают пустые блоки на сайте.
- 2 712 блоков чтения, 27 таблиц, 8 встроенных PNG-рисунков, 419 абзацев со списочной нумерацией.
- 77 математических выражений OMML, содержащих 212 математических текстовых фрагментов.
- 59 502 слова и 470 732 символа в блоках. Эта техническая оценка включает сохранённый бумажный индекс и не включает названия верхнего уровня, хранимые отдельно.
- **34 000 из 34 000 текстовых узлов** тела DOCX обработаны ровно один раз. Проверка включает обычный текст, математический текст, таблицы и оглавление внутри content control.
- В файлах footnotes/endnotes находятся только системные разделители; авторских сносок и концевых примечаний в этой редакции нет.
- Первая основная глава: «ГЛАВА 1. ОТ ЗНАНИЯ К ПОЛНОМОЧИЮ». Последняя: «ГЛАВА 18. РУТ (МИИТ) КАК ПОЛИГОН НОВОЙ АРХИТЕКТУРЫ».
- Последний блок рукописи — библиографическая запись № 72 о ГОСТ Р 7.0.108—2022; она сохранена полностью.

Импортёр завершает работу ошибкой, если хотя бы один исходный текстовый узел не обработан ровно один раз, появляются повторяющиеся идентификаторы разделов, неразрешённые рисунки или неподдерживаемые вложенные таблицы/рисунки внутри таблиц. Никакие выходные файлы не заменяются до успешного завершения извлечения и проверки покрытия.

## Файлы и контракт для UI

- `src/data/book.json` — данные, Unicode UTF-8, без HTML.
- `src/lib/book.ts` — типы и функции чтения.
- `public/book/figures/*.png` — 8 исходных изображений, извлечённых из DOCX без изменения байтов.
- `scripts/import-manuscript.py` — повторяемый импорт, только стандартная библиотека Python.

Основной объект содержит `title`, `subtitle`, `edition`, `publicationStatus`, `source`, `parts`, `chapters`, `notes`, `statistics`.

Раздел: `{id, number, title, part, kind, status, publicationStatus, blocks}`.

- `number`: число для глав, кириллическая буква для приложений, `null` для остальных разделов.
- `part`: исходное полное название части или `null`.
- `kind`: `frontmatter | chapter | appendix | backmatter`.
- `status`: `available | planned`; **все импортированные разделы доступны**.
- `publicationStatus`: `draft | published`; **все импортированные разделы — авторская рабочая редакция**. Наличие текста не означает завершённую издательскую публикацию.
- Стабильные идентификаторы: `introduction`, `preface`, `chapter-01` … `chapter-18`, `appendix-a` … `appendix-k`, `conclusion`, `references`.

Блоки:

- `paragraph`: `text`, необязательные `role: quote | caption`, `list: {kind, level, marker, sourceNumberId}`, `math`.
- `heading`: `text`, `level`; уровень из стиля Word или авторского стиля подзаголовков приложения К.
- `table`: `rows: string[][]`; абзацы внутри ячейки разделены переводом строки. `cellLayout` сохраняет ширину объединённых ячеек и вертикальное объединение, если они появятся. В текущей редакции вертикальных объединений нет.
- `image`: `src`, `alt`, `width`, `height`. Подпись рисунка остаётся отдельным следующим текстовым блоком. Номера подписей сохранены как в рукописи, включая повторы.

Каждый блок имеет `id`, привязанный к порядку элементов DOCX. Названия разделов хранятся в `chapter.title`, названия частей — в `book.parts` и `chapter.part`; в начало блоков они второй раз не дублируются.

Экспорты: `book`, `chapters`, `mainChapters`, `appendices`, `readingChapters`, `getChapter(id)`, `getBlockText(block)`, `getChapterText(chapter)`, `getChapterReadingMinutes(chapter)`, `getChapterNeighbors(id)`.

Для веб-навигации используйте `readingChapters`: он исключает только `source-contents` — 279 строк оригинального бумажного оглавления с номерами страниц. Само исходное оглавление остаётся в JSON; содержание сайта строится по разделам и подзаголовкам.

## Особенности представления

Текст не переводится, не сокращается и не дописывается. Сохраняются Unicode, явные табуляции и переводы строк. Пустые абзацы, мягкие переносы Word, колонтитулы, разметка страниц, форматирование шрифтов и инструкции полей Word не являются текстом читалки. Сохранённый результат поля оглавления импортирован; команды поля не выполняются.

Формулы представлены линейно: нижний индекс `_{...}`, верхний `^{...}`, дробь `(...)/(...)`, скобки сохранены. Это сохраняет текст и структуру формул без зависимости от шрифтов Word. Исходное OMML каждого выражения сохранено в `block.math[].omml` для возможного будущего математического рендеринга. **Нельзя вставлять OMML/строки рукописи через raw HTML**: React должен выводить содержимое как текст. Точная типографика формул и оформления DOCX в эту версию импорта не входит.

Сведения о биографиях и корректность фактов внутри книги импортёр не проверяет. Сведения на отдельной странице авторов могут иметь собственную редактуру и источники; этот файл остаётся авторской рукописью.

## Обновление

Из корня репозитория:

```powershell
python scripts/import-manuscript.py "$env:USERPROFILE\Downloads\Pravo_na_reshenie_04.09.26.docx" --edition 2026-09-04
python scripts/import-manuscript.py "$env:USERPROFILE\Downloads\Pravo_na_reshenie_04.09.26.docx" --edition 2026-09-04 --check
npm run typecheck
```

Передавайте фактическую дату новой редакции через `--edition`. Импорт заменяет JSON целиком и перезаписывает только рисунки текущего источника; не удаляет другие файлы. Для постепенного пополнения достаточно импортировать следующую авторскую редакцию и проверить diff. Будущие главы не создаются автоматически и не заполняются вымышленным текстом.

`--check` не пишет файлы: заново извлекает рукопись, сравнивает весь JSON и каждый рисунок побайтно с текущим результатом. Первоначальная проверка воспроизводимости пройдена. Проверка TypeScript выполняется вместе с общей сборкой сайта.
