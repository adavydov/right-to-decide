# Издательская сборка 10.0

12 сентября 2026 года. Установлен принятый корпус 10.0: пролог, 24 главы, эпилог, 39 примечаний и полный PDF на 91 странице. Идентичность выпуска — `literary-manuscript-v10.0-5a384c35b7b1`; состав и результаты экспорта зафиксированы в `manuscript/v10/release-manifest.json`. Внешняя публикация выполняется отдельно через GitHub Pages.

## Входной формат

Единственный каталог: `book-v10/manuscript/chapters`. Ровно 26 литературных файлов: `P00.md`, `C01.md` … `C24.md`, `E00.md`. Порядок и названия сверяются с `book-v10/planning/chapters.json`. Методическая заметка и публичные досье оформляются отдельно; они не маскируются под главу.

UTF-8, обычные окончания строк. Первая строка — `# Точное название`. Для C01 допустимо `# Глава 1. Точное название`. Номер должен совпадать с ID. Между абзацами, заголовками, списками и таблицами — пустая строка. Подзаголовки `##` и `###`. Поддерживаются **жирный**, *курсив*, `код`, открытые HTTP(S)-ссылки, простые списки и разделитель `---`.

```markdown
# Точное название

Абзац с утверждением.[1]

## Подзаголовок

| Параметр | Значение |
| --- | --- |
| Условие | Результат[2] |

## Примечания

[1] Автор. Название. Страница. [Источник](https://example.org/)

Продолжение того же примечания отдельным абзацем.

[2] Другое примечание.
```

Нумерация примечаний начинается заново в каждом файле, `[1]` … `[N]`. Ссылка может стоять в ячейке таблицы. Определения без ссылок, ссылки без определений и повторы номеров отклоняются. Синтаксис `[^1]`, HTML, YAML, изображения, цитатные блоки `>`, вложенные таблицы и таблицы внутри примечаний не поддерживаются. Труба внутри ячейки потребует переформулировать ячейку; её экранирование не поддерживается старым проверенным парсером. Локальные файловые ссылки и пути частной библиотеки запрещены в публичном тексте.

## Приёмка

`book-v10/editorial/acceptance-v10.json` создаёт интегратор **после** фактических проверок. Сборщик его не создаёт и не переводит главы в принятый статус. Структура:

- `schemaVersion: 1`, `editionVersion: "10.0"`, `decision: "accepted-for-release"`, фактический `releaseDate` в формате YYYY-MM-DD.
- `policies`: ровно записи `{path, sha256}` для `CONSTITUTION.md`, `planning/chapters.json`, `editorial/QUALITY_GATES.md` относительно `book-v10`.
- `sources`: ровно P00, C01…C24, E00; каждая запись имеет `id`, `path: "manuscript/chapters/<ID>.md"`, SHA-256 **байтов** файла, `author`, отличный от него `independentReviewer`, `decision: "accepted"`, `unresolvedMaterialIssues: 0`, `evidence: {path, sha256}`. Имена отражают фактических исполнителей. Evidence — компактное свидетельство фактического чтения с исполнителем, решением и точным SHA. Эти свидетельства копируются в публичный Git вместе с приёмкой; полные частные досье и карточки в них не включаются.
- `sourceSetSha256`: SHA-256 UTF-8 JSON из упорядоченных `{id,path,sha256}`, формат `ensure_ascii=False`, `indent=2`, завершающий LF. Команда ниже выдаёт готовое значение; вручную его вычислять не надо.
- `wholeBook`: записи `continuousReading`, `factualReview`, `alternativesReview`, `continuityReview`, `repetitionReview`. У каждой `reviewer`, `decision: "accepted"`, тот же `sourceSetSha256`, `evidence: {path,sha256}`.
- `authorApproval`: такая же запись reviewer/decision/sourceSetSha256/evidence. Она фиксирует имеющееся прямое поручение пользователя и решение выпускающего интегратора после проверок. Дополнительный запрос разрешения этим полем не вводится. Агентные проверки не называются человеческой или внешней экспертизой.

Все пути evidence относительно `book-v10`, без `..`. Поддерживается необязательное поле `bytes`. Изменение любого из 26 файлов инвалидирует его проверку и общую приёмку. Проверка формата не определяет литературное качество; она проверяет происхождение и согласованность фактически оформленных решений.

## Команды из корня worktree

Публичные модельные досье подаются отдельным принятым пакетом `book-v10/public/research-v10/`: `index.md`, `M01.md`…`M04.md`, `manifest.json`. До его появления маршрут `/research/v10/` не показывает заглушку. Стабильные ссылки: `/research/v10/#M01` … `#M04`.

У manifest.json поля `decision: "accepted"`, `reviewer` (фактический исполнитель), `texts` — пять записей `{id: "INDEX" | "M01"…"M04", path: "public/research-v10/index.md" | "public/research-v10/M01.md"…, sha256}`. Необязательный `downloads` — белый список `{modelId, path, name, label, sha256}`. `path` относительно `book-v10` должен находиться в `models/`, `name` — уникальное публичное имя без каталогов, с расширением `.py`, `.csv`, `.json` или `.md`. Сборщик не обходит каталог рекурсивно и не берёт частную библиотеку. Названный пакет обязателен для подготовки 10.0; его хеши входят в идентичность выпуска. Тексты используют тот же Markdown, что главы.

В Windows используйте Python из доступного runtime, включив его каталог в PATH. Для подготовки PDF нужны `pypdf` и LibreOffice по установленному пути `C:\Program Files\LibreOffice\program\soffice.exe`. Проверка установленного выпуска и CI не запускают конвертацию PDF; проверяются зафиксированные байты.

```powershell
python scripts/release_v10.py source-set --source ../book-v10
python scripts/release_v10.py prepare --source ../book-v10 --stage .release-staging/v10
python scripts/release_v10.py check --stage .release-staging/v10
```

`prepare` требует отсутствующий каталог назначения: предыдущую подготовку не перезаписывает. Для повторения после исправлений задайте другое имя стадии. До проверки приёмки не создаётся ни одного файла результата. После ошибки конвертации неполная стадия остаётся для диагностики; установить её нельзя.

Подготовка создаёт только локальную стадию: точный JSON, все исходные Markdown, отдельные DOCX глав, целые DOCX/PDF/Markdown, копии evidence и манифест с хешами. В веб-версии и отдельных DOCX сохраняется локальная нумерация примечаний. В целом Word/PDF примечания собраны в конце с глобальной последовательной нумерацией. Целый Markdown сохраняет самостоятельные разделы и их локальные примечания; повторно подавать его вместо 26 исходников нельзя.

После визуальной проверки **реальных** DOCX/PDF и финального решения выпускающего:

```powershell
python scripts/release_v10.py install --stage .release-staging/v10
$env:NEXT_PUBLIC_EDITORIAL_MODE='static'
$env:NEXT_PUBLIC_BASE_PATH='/right-to-decide'
npm run editorial:build
npm run check
```

`install` только переключает локальный checkout. Коммит, push и GitHub Pages — отдельные действия root в рамках уже данного поручения пользователя. Изменённые исходники 9.0, неизвестная активная редакция или нарушенная стадия блокируют установку. После установки `npm run check` автоматически выбирает проверку 10.0. Исторические тесты и генераторы 9.0 сохраняются.

## Архив и заметки

`src/data/edition-v9.json` — точная байтовая копия принятого book.json 9.0. `archive-v9.json` фиксирует старую рукопись, все скачиваемые файлы и все исторические опубликованные снимки. До и после установки их хеши проверяются. Старый архив первоначального DOCX не заменяется.

Читатель выбирает сохранённую 9.0 на `/editions/v9/`; полная читалка — `/editions/v9/read/<chapter>/`. Исходные IDs и ссылки на примечания сохраняются. Новая редакция использует `prologue`, `chapter-01` … `chapter-24`, `epilogue`, а каждый блок получает префикс `manuscript-v10-<chapter>-<SHA256 исходника, 12 знаков>`. Совпадение номера главы не является основанием перенести заметку.

Личные заметки не изменяются и не экспортируются в редакционный корпус. Кнопка исходного текста разрешает привязку по **edition_id + chapter_id + block_id**. Для 9.0 открывается архивная читалка с исходным DOM ID; для других старых редакций — их неизменяемый опубликованный снимок. Новые сохранённые позиции чтения отделены пространством редакции. Старые позиции читаются только при совпадающем хеше текста.

## Техническая проверка

`python scripts/test-release-v10.py`: небольшая fixture вне книги, реальные локальные Word/PDF, таблица со сноской, целостность ссылок, строгие IDs, отказ без приёмки/с неполным корпусом/устаревшим хешем/самоприёмкой. Fixture не является главой и удаляется вместе с временным каталогом. На CI без LibreOffice локальный тест конвертации явно пропускается; проверка опубликованных артефактов обязательна.

Результаты экспорта находятся в манифесте выпуска, происхождение литературной приёмки — в `manuscript/v10/evidence/editorial/acceptance-v10.json`. Технические журналы, снимки браузера и материалы визуального референса сохраняются локально вне Git. Полный публичный прогон выполняет workflow `Validate and deploy GitHub Pages`.

## Принятые публичные пакеты библиотеки и редакции

Помимо досье моделей сборка требует два отдельных пакета. Приёмка всех трёх не принимает литературную рукопись автоматически.

- public/library-v10/manifest.json: schemaVersion 1, editionVersion 10.0, decision accepted, author и отличный от него reviewer; catalog {path: public/library-v10/catalog.json, sha256}; counts {records, recordsWithCards, cards}. Каталог содержит только schemaVersion, asOf, summary, readingNote, sources. Каждая запись: id, title, authors, edition, category, annotation, role, cardCount, reading {kind,label,scope}, links [{label,url}]. Сборщик проверяет белый список и суммы, не обращаясь к частной библиотеке.
- public/editorial-v10/manifest.json: decision accepted, author, отличный reviewer; team {path: public/editorial-v10/team.json,sha256}, text {path: public/editorial-v10/team.md,sha256}, manifesto {path: public/editorial-v10/manifesto.md,sha256}. Ровно 13 ролей, существующие roleIds в workflow, только темы принятой библиографии. Манифест использует обычный Markdown того же парсера.

Все пути относительно book-v10. Значения SHA относятся к фактическим байтам. Manifest сохраняется во внутренней идентичности выпуска; публичная проекция не получает reviewer, evidence или пути частного архива. Подготовка фиксирует пакеты и повторно сверяет их после конвертации.

При установке 10 основной каталог и описание редакции переключаются вместе с книгой. На /editions/v9/library/, /editions/v9/editorial/, /editions/v9/editorial-team.json и /editions/v9/manifesto/ остаётся прежняя редакция. Скачивания старой конституции сохраняют первоначальные адреса. archive-library-v9.json и archive-editorial-v9.json защищают её данные от незаметной подмены.

Архивные реестры закрепляют канонические байты прежнего Git-коммита. Четыре JSON, которые Windows автоматически открывал с CRLF, возвращены к прежним Git-байтам LF; адресные правила `.gitattributes` сохраняют их при последующих checkout. Текст и публичные файлы версии 9 не изменены.
